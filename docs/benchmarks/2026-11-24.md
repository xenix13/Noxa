## What it shows

- **Memory:** Noxa uses 3 to 5 times less memory than the others, idle, while streaming and while converting.
- **Response times:** Noxa's pages answer about twice as fast as Jellyfin's and three times as fast as Plex's. The library is small, though: a larger library may change this.
- **First launch:** it measures the very first launch, initial setup included, not a normal restart. This was measured on purpose: Noxa only loads what it needs. Jellyfin and Plex create their database and load their plug-ins at that point, so a plain restart is much shorter for them.
- **Conversion is Noxa's weak spot:** it runs at 1.10× real time against about 1.45×, with the same two cores fully busy. Two things are already known:
  - It is not ffmpeg itself: Noxa's ffmpeg (Ubuntu's 6.1) runs the same command as fast as Jellyfin's.
  - Part of the gap comes from encoder settings. Jellyfin uses faster x264 options, measured at about +10 % with the same quality.

  Fixing this is on the roadmap for the next fix releases, and the benchmark will be run again afterwards.
- **Scan:** Noxa 4.1.4 scanned a library added during another scan only afterwards. The benchmark found this bug, and it is fixed in 4.2.0.

## Limits

- One machine and one run.
- The video is a generated test pattern, not real films. Compare the servers with each other, not with other benchmarks.
- The *background work after the scan* row was not valid in this run (the end-of-work test was too strict) and is left out. It is fixed in the kit.
